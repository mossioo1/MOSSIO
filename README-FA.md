# MOSSIO — CLASSIFIED CREATIVE NETWORK

بسته آماده استقرار وب‌سایت MOSSIO با رابط موبایل‌محور، ویدیوی ورود، موسیقی قابل روشن/خاموش کردن، بخش‌های محتوایی و پنل مدیریت متصل به بک‌اند واقعی.

> **وضعیت تحویل:** کد و دارایی‌ها در این بسته ساخته شده‌اند؛ سایت هنوز روی اینترنت منتشر نشده و هیچ حساب Cloudflare، دیتابیس یا فضای ذخیره‌سازی به آن متصل نیست. برای انتشار، باید مراحل راه‌اندازی یک‌باره زیر در حساب خودتان انجام شود. این بسته از GitHub Pages استفاده نمی‌کند.

## امکانات موجود

- صفحه معرفی سینمایی با انیمیشن شروع و امکان رد کردن آن
- نمایش ویدیوی معرفی 1080p و پخش با کنترل کاربر
- موسیقی پس‌زمینه با دکمه روشن/خاموش؛ بدون autoplay اجباری
- بخش‌های معرفی، پروژه‌ها، گالری، ابزارها، مهارت‌ها، تایم‌لاین، اخبار و ارتباط
- پنل مدیریت `/admin/` با ورود مدیر، مدیریت محتوا، تنظیمات سایت و آپلود رسانه
- ذخیره دائمی اطلاعات در Cloudflare D1 و فایل‌های آپلودی در R2
- رمز عبور مدیر با PBKDF2، نشست HttpOnly/Secure، محدودیت تلاش ورود و اعتبارسنجی نوع/حجم فایل سمت سرور

## معماری و سرویس‌ها

این بسته برای **Cloudflare Workers + Static Assets + D1 + R2** آماده شده است:

- Frontend: HTML/CSS/JavaScript بدون نیاز به build و framework سنگین
- Backend: Cloudflare Worker (`worker/index.js`)
- Database: Cloudflare D1 (SQLite)
- Media Storage: Cloudflare R2
- Authentication: نشست سروری و کوکی HttpOnly/Secure/SameSite=Strict
- Hosting: Cloudflare Workers Static Assets، نه GitHub Pages
- Domain: فعلاً زیردامنه رایگان `workers.dev`؛ دامنه سفارشی `.com` رایگان نیست و فعلاً خریداری نشده است
- Backup: خروجی دوره‌ای D1 و نگهداری نسخه رسانه‌ها در آرشیو جداگانه

پلن‌ها، سقف مصرف و قیمت‌ها ممکن است تغییر کنند. پیش از فعال‌سازی، صفحه قیمت‌گذاری Cloudflare را بررسی کنید. پلن رایگان به معنی نامحدود بودن نیست. R2/D1/Workers باید در داشبورد همان حساب فعال و متصل شوند.

## راه‌اندازی از گوشی اندروید (بدون CMD)

### A) ساخت مخزن خصوصی GitHub

1. در مرورگر گوشی وارد GitHub شوید و یک Repository جدید با نام `mossio-classified` بسازید.
2. ترجیحاً آن را **Private** انتخاب کنید.
3. فایل ZIP این پروژه را از حالت فشرده خارج کنید و محتویات پوشه `MOSSIO-CLASSIFIED` را در مخزن بارگذاری کنید. می‌توانید از گزینه Upload files در وب‌سایت GitHub استفاده کنید؛ فایل‌های بزرگ ممکن است نیاز به بارگذاری جداگانه داشته باشند.
4. فایل‌های `originals/` فقط آرشیو هستند و برای اجرای سایت لازم نیستند؛ اگر محدودیت حجم مخزن داشتید، آن‌ها را خارج از مخزن نگه دارید.

### B) ساخت D1

1. در داشبورد Cloudflare وارد Workers & Pages → D1 SQL Database شوید.
2. یک دیتابیس با نام `mossio-db` بسازید.
3. شناسه Database ID را کپی کنید.
4. در GitHub فایل `wrangler.toml` را ویرایش کنید و مقدار `REPLACE_WITH_D1_DATABASE_ID` را با شناسه واقعی جایگزین کنید.
5. جدول‌ها باید با اجرای migration فایل `migrations/0001_initial.sql` ساخته شوند. از بخش D1 → Console محتوای همین فایل SQL را اجرا کنید.

### C) ساخت R2

1. در Cloudflare → R2 بسازید/فعال کنید.
2. یک bucket با نام دقیق `mossio-media` بسازید.
3. نام binding در تنظیمات Worker باید `MEDIA` و نام bucket باید `mossio-media` باشد.

### D) اتصال GitHub به Worker Builds

1. از داشبورد Cloudflare وارد Workers & Pages شوید و Create application / Connect to Git را انتخاب کنید.
2. مخزن `mossio-classified` را متصل کنید.
3. برای build/deploy از Wrangler استفاده کنید. اگر داشبورد فیلد Build command نشان می‌دهد، `npx wrangler deploy` را قرار دهید؛ ریشه پروژه همان پوشه‌ای است که `wrangler.toml` در آن قرار دارد.
4. مطمئن شوید پروژه به‌صورت Worker با Static Assets منتشر شده، نه GitHub Pages.
5. در تنظیمات Worker، binding دیتابیس را با نام `DB` به D1 `mossio-db` و binding آبجکت را با نام `MEDIA` به R2 `mossio-media` متصل کنید. اگر bindingها از `wrangler.toml` خوانده می‌شوند، بعد از deploy صحت آن‌ها را بررسی کنید.
6. در Worker → Settings → Variables and Secrets یک Secret با نام `ADMIN_SETUP_KEY` بسازید. یک مقدار تصادفی و طولانی انتخاب کنید و آن را در جای امن نگه دارید.
7. مقدار `SESSION_TTL_DAYS` به‌صورت پیش‌فرض 7 و `MAX_UPLOAD_MB` به‌صورت پیش‌فرض 25 است.

### E) ساخت مدیر اولیه

پس از deploy، آدرس سایت را باز کنید و به `/admin/` بروید. بخش First-time setup را باز کنید و همان `ADMIN_SETUP_KEY` را وارد کنید. نام کاربری ۳ تا ۳۲ کاراکتر و رمز عبور حداقل ۱۲ کاراکتر باشد. پس از ساخت مدیر، setup دیگر قابل استفاده نیست.

### F) تست نهایی

- `https://YOUR-WORKER.workers.dev/api/health` باید وضعیت API را نشان دهد.
- در `/admin/` وارد شوید.
- یک خبر آزمایشی بسازید، آن را Published کنید و صفحه اصلی را بازخوانی کنید.
- یک تصویر کوچک آپلود کنید و URL بازگشتی را در Media URL یک آیتم قرار دهید.
- موسیقی را فقط با دکمه MUSIC روشن کنید.
- ویدیوی شروع باید با دکمه Enter یا Skip قابل عبور باشد.

## نکات امنیتی و عملیاتی

- رمز عبور مدیر را در HTML/JavaScript قرار ندهید.
- `ADMIN_SETUP_KEY` باید فقط به‌صورت Secret در تنظیمات Worker ذخیره شود؛ هرگز در مخزن Git قرار نگیرد.
- مخزن را Private نگه دارید؛ فایل‌های مادر 4K و صوت اصلی را بهتر است داخل Git قرار ندهید.
- آپلود پیش‌فرض حداکثر 25MB است؛ برای ویدئوهای بزرگ‌تر باید سقف و محدودیت‌های واقعی Worker/R2 و هزینه احتمالی بررسی شود.
- در نسخه فعلی فایل‌های آپلودشده در R2 از طریق مسیر `/media/` عمومی قابل دریافت‌اند؛ پنل و تغییر محتوا محافظت شده‌اند. فایل‌های خصوصی/محرمانه را آپلود نکنید.
- برای بکاپ D1 از Export/Backup داشبورد Cloudflare استفاده کنید و نسخه‌های اصلی رسانه را جداگانه نگه دارید.
- برای امنیت بالاتر، قبل از انتشار عمومی، یک تست عملی ورود ناموفق، انقضای نشست، آپلود فایل غیرمجاز و محدودیت حجم انجام دهید.

## محدودیت‌های فعلی که شفاف باید بدانید

- هیچ دامنه `.com` خریداری یا رزرو نشده است.
- سایت هنوز deploy نشده؛ آدرس عمومی واقعی تا اتصال حساب Cloudflare ایجاد نمی‌شود.
- محتوای پروژه‌ها، اخبار، گالری و مهارت‌ها با داده‌های اولیه/نمونه شروع می‌شود و از پنل قابل تغییر است.
- این بسته پیاده‌سازی فنی را فراهم می‌کند، اما اتصال سرویس‌های Cloudflare و ایجاد حساب مدیر نیازمند اقدام صاحب حساب است.
- رابط و پنل برای موبایل طراحی شده‌اند؛ فرآیند اتصال Git و تنظیم bindingها ممکن است بسته به نسخه داشبورد Cloudflare تغییر کند.
